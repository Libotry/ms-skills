## 一、总体原则

### [SEC-1.1] 保证静态类型安全 `[适用: All]`

**严重度**:高

- 禁止隐式窄化转换(`int64_t → int32_t`)
- 禁止使用 C 风格强制转换,优先使用 `static_cast` / `reinterpret_cast`
- 模板实例化必须显式指定类型

### [SEC-1.2] 保证内存安全 `[适用: All]`

**严重度**:高

- 所有动态分配必须有释放路径
- 禁止内存泄漏
- 禁止 use-after-free

### [SEC-1.3] 禁止使用未定义行为 `[适用: All]`

**严重度**:高

- 禁止 signed integer overflow
- 禁止空指针解引用
- 禁止访问越界数组
- 禁止未初始化变量使用

---

## 二、数值运算安全

### [SEC-2.1] 有符号整数运算不溢出 `[适用: All]`

**严重度**:高

**问题**:Tiling 中常见的 `int32_t batch * int32_t channels` 可能溢出。

**正确做法**:升级到 `int64_t` 后计算。

### [SEC-2.2] 无符号整数运算不回绕 `[适用: All]`

**严重度**:高

**问题**:`uint32_t * uint32_t` 会先在 32 位下计算后截断,即使赋给 uint64 也是错的。

**正确做法**:第一个操作数显式 cast 到 `uint64_t`:`(uint64_t)a * b`

### [SEC-2.3] 除法/余数运算除零保护 `[适用: All]`

**严重度**:高

**问题**:除数为 0 是 UB。

**正确做法**:除法前显式检查 `if (divisor != 0)`。

---

## 三、内存与指针安全

### [SEC-3.1] 禁止使用未初始化的变量 `[适用: All]`

**严重度**:高

所有变量必须在使用前初始化。

### [SEC-3.2] 资源释放后指针置新值 `[适用: Tiling]`

**严重度**:中

`free(p); p = nullptr;` 防止 use-after-free。

### [SEC-3.3] 数组索引校验 `[适用: All]`

**严重度**:高

所有数组下标访问前必须检查 `< size`。

### [SEC-3.4] 禁止 sizeof 指针 `[适用: All]`

**严重度**:中

```cpp
// ❌ 错误:得到指针大小(8 字节),不是数组大小
int* arr = malloc(10 * sizeof(int));
size_t n = sizeof(arr) / sizeof(arr[0]);  // n = 2(不是 10)
```

### [SEC-3.5] 指针使用前判空 `[适用: All]`

**严重度**:高

所有指针解引用前必须 `if (p != nullptr)`。

### [SEC-3.6] 字符串存储有足够空间 `[适用: Tiling]`

**严重度**:高

`char buf[10]; strcpy(buf, "hello world");` 越界。

---

## 四、输入验证

### [SEC-4.1] 外部输入合法性校验 `[适用: All]`

**严重度**:高

Tiling 中接收的 shape、dtype 必须校验范围。

### [SEC-4.2] 内存操作长度校验 `[适用: All]`

**严重度**:高

`memcpy(dst, src, len)` 前必须确认 `len <= dstCapacity && len <= srcSize`。

---

## 五、资源管理(仅 Tiling)

### [SEC-5.1] 资源申请后判断是否成功

**严重度**:高

`malloc` / `new` 返回值必须判空。

### [SEC-5.2] 资源泄露防护

**严重度**:高

所有 `new` / `malloc` 必须有对应 `delete` / `free` 路径(包括异常路径)。

### [SEC-5.3] new/delete 配对使用

**严重度**:高

`new[]` 对应 `delete[]`,`new` 对应 `delete`。

### [SEC-5.4] new 操作符错误处理

**严重度**:高

`new (std::nothrow)` 或 try-catch。

---

## 八、安全函数(仅 Tiling)

### [SEC-8.1] 使用安全函数替代危险函数

**严重度**:高

| 危险函数 | 安全替代 |
|---------|---------|
| `strcpy` | `strncpy_s` |
| `strcat` | `strncat_s` |
| `sprintf` | `snprintf_s` |
| `memcpy` | `memcpy_s` |
| `gets` | `fgets` |

### [SEC-8.2] 正确设置安全函数 destMax 参数

**严重度**:高

`strncpy_s(dest, sizeof(dest), src, ...)`。

### [SEC-8.3] 检查安全函数返回值

**严重度**:高

所有 `*_s` 函数的返回值必须检查。

---

## 九、类与对象

### [SEC-9.1] 禁止逐位操作非 trivially copyable 对象 `[适用: All]`

**严重度**:中

`memcpy` / `memcmp` 只能用于 trivially copyable 类型(如 POD、自带拷贝构造)。

---

## 十、标准库

### [SEC-10.1] 禁止从空指针创建 std::string `[适用: Tiling]`

**严重度**:高

`std::string s(nullptr);` 是 UB。

### [SEC-10.2] 不要保存 c_str/data 指针 `[适用: Tiling]`

**严重度**:中

`const char* p = s.c_str(); s.append("x");` 后 `p` 失效。

### [SEC-10.3] 敏感信息使用后清零 `[适用: All]`

**严重度**:高

`memset(password, 0, sizeof(password));` 后再 free。

### [SEC-10.4] 结构体字段末尾添加 `[适用: All]`

**严重度**:中

二进制兼容:不要在结构体中间插入字段,应追加到末尾。

### [SEC-10.5] 接口变更考虑兼容性 `[适用: All]`

**严重度**:中

公开 API 的签名变更需保持 ABI 兼容。

---

## 十一、LOG API 安全(仅 Tiling)

### [SEC-11.1] LOG API 禁止传入空指针

**严重度**:高

`LOG_ERROR("ptr=%s", nullptr);` 是 UB。

### [SEC-11.2] LOG API 参数必须与格式化占位符逐位一致

**严重度**:高

`LOG_INFO("x=%d", "hello");` 类型不匹配是 UB。

### [SEC-11.3] LOG API 禁止传入已释放内存的指针

**严重度**:高

`free(p); LOG_INFO("p=%s", p);` 是 use-after-free。

### [SEC-11.4] LOG 消息英语行文语法正确

**严重度**:低

国际化要求。

---

## 950PR 特别注意

- **Kernel 侧(std:: 限制)**:Kernel 侧标准 C++ 库支持有限,优先使用 Ascend C API(见 `ascendc-api.md`)。
- **RegBase 路线**:RegBase 路线下 std:: 限制更严格,大量容器/算法不可用。
- **SIMT 路线**:SIMT 函数内禁止使用 std::(运行时不支持)。
